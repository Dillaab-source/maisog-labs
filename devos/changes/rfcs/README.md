# RFCs

Filed RFCs live here as `ML-DEVOS-RFC-<NNN>.md`, using `../../templates/RFC_TEMPLATE.md`. Numbering is sequential starting at `001`, never reused. See `../../governance/change-policy/CHANGE_GOVERNANCE_POLICY.md` §3 for what an RFC is (and is not) evidence of.

## Current contents

- `ML-DEVOS-RFC-006.md` — MaisogLabs `WEB-INC-003` project-mutation capability proposal. Classified `CAPABILITY`, approved by `ML-DEVOS-AS-020`, and bounded local/repository implementation authorized by `D-027`. It permits project create-draft, immutable-revision edit-draft, protected preview, publish, and unpublish only; schema change, project delete, other-domain mutation, remote D1, public cutover, deployment, and later WEB-INC work remain separately gated.
- `ML-DEVOS-RFC-005.md` — MaisogLabs `WEB-INC-008` append-only audit-substrate architecture proposal. Classified `ARCHITECTURE`, approved by `ML-DEVOS-AS-017`, and bounded local/repository implementation authorized by `D-026`. It permits exactly one new `audit_log` table and a server-only append primitive; editorial mutation, remote D1, deployment, public cutover, and later WEB-INC work remain separately gated.
- `ML-DEVOS-RFC-004.md` — MaisogLabs `WEB-INC-002` protected read-only admin-dashboard architecture proposal. Classified `ARCHITECTURE`, approved by `ML-DEVOS-AS-015`, and implementation authorized by `D-025`. It permits only an authenticated bounded read endpoint over the local WEB-INC-005 D1 substrate; writes, remote D1, public cutover, deployment, and later WEB-INC work remain separately gated.
- `ML-DEVOS-RFC-003.md` — MaisogLabs `WEB-INC-005` D1 revision-substrate/current-content migration architecture proposal. Classified `ARCHITECTURE`, approved by `ML-DEVOS-AS-013`, and implementation authorized by `D-024`. Remote D1 creation/migration, public cutover, deployment, and protected/main merge remain separately gated and are not authorized by the RFC.
- `ML-DEVOS-RFC-002.md` — MaisogLabs `WEB-INC-001` authentication-boundary product architecture proposal. Classified `ARCHITECTURE`, reviewed and approved by `ML-DEVOS-AS-011`, and implementation authorized by `D-023`. Production Cloudflare Access configuration and deployment remain separately gated and are not authorized by the RFC.
- `ML-DEVOS-RFC-001.md` — S2 DevOS Repository Foundation. Filed under `D-015`, reviewed by `ML-DEVOS-AS-006`, implemented under `D-016` (`c76bf6a`), and closed at Sentinel `v1.4.0` under `D-017`/`ML-DEVOS-ADR-002`. Its own text is preserved unedited as the historical proposal record; its status banner records the closure outcome, per `CHANGE_GOVERNANCE_POLICY.md` §3's rule that an accepted RFC is never itself rewritten into an ADR.

No RFC had been filed as of S1 — the RFC/ADR system did not exist yet at that point (`D-012`/`ML-DEVOS-AS-003`'s pre-RFC bootstrap principle). `ML-DEVOS-RFC-001` is the first RFC actually filed under the system S1 built.
