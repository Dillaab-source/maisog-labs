- `ML-DEVOS-RFC-019.md` — Sentinel S6 Isolated Execution. `DRAFT` `ARCHITECTURE`-class proposal, authorized for discovery/design only by `D-066`. Revised in Remediation Cycles 1–3 (`ML-DEVOS-AS-086`, `ML-DEVOS-AS-087`, `ML-DEVOS-AS-088`/`D-067`) and Architect-approved by `ML-DEVOS-AS-089`. Then amended under `D-069`, after a session safety control blocked a generic command-running surface during the suspended `D-068` implementation, and resubmitted for Architect review of the amendment. S6 core now exposes no command-execution primitive; actor- and tool-chosen commands run only in a separately authorized execution driver, under single-use Execution Permits. Each permit binds the canonical S5 `shell.exec` capability decision, which is not argv-aware, to S6's exact argv digest, with request-level idempotency and fail-closed handling of claimed-but-unreported permits (§13.1, as remediated for `ML-DEVOS-AS-090`). Defines four named isolation levels (Git branch, Git working tree, filesystem/process/environment, OS/container/VM sandbox) and proposes V1 = a dedicated clone per execution instance plus an L3 environment boundary. V1 explicitly does not contain a deliberately hostile same-user process. It also defines:
  - task → repository/base-SHA/branch/workspace/instance identity;
  - exact-base and freshness rules; dirty/untracked handling;
  - path, symlink and junction confinement; the allowlist-built environment and the credential non-copy policy;
  - dependency/cache isolation; the environment lifecycle, concurrency, crash/orphan recovery and stale-lease handling;
  - Windows/POSIX profiles; 30 ordered fail-closed reason codes; provenance outputs; and a failure-injection/mutation test plan.

  Composition: S3 scope is consumed by reference, S4 ownership/lease/fencing is reused (publication is linearized at S4 `transition`), and S5 decisions are consumed unchanged (MAY / CAN / ISOLATED stay separate). The immutable instance identity is separate from a gap-free S4-derived Fencing Checkpoint. Independent QA reconstructs from the commit named by an S6-owned Result Transfer Record, proven current against S4 through public operations only. The Builder publication transition carries one fixed `evidenceRef` payload (`evidenceClass: "ACTOR_REPORTED"`) that satisfies S4's existing guard and is replayed byte-identically. Host-side Git transport is a separately authorized, `CORE-019`-scoped execution-transport action. The RFC recommends `devos/execution/` as S6's future canonical home but creates no root, file or manifest change, and implements nothing. The amendment was approved by `ML-DEVOS-AS-093`. A bounded S6-core implementation is in progress under `D-071`: `devos/execution/` is now the registered S6 root with `status: NOT_IMPLEMENTED`, `executable_runtime_present: false` and no `closure_ref`. It is not closed, and Sentinel stays `v1.8.0`. After `ML-DEVOS-AS-094`–`ML-DEVOS-AS-097` found one recurring class of state-integrity defect, implementation was paused under `D-073`. The RFC was amended (per `ML-DEVOS-AS-098`) with one local transaction boundary per task, prepare → effect → reconcile for external effects, an S6-owned one-active-environment invariant, fail-closed `PENDING` attribution, a closed public surface, provenance as a projection with an explicit S7 boundary, and a persistence-point crash matrix. The amendment is resubmitted for Architect review; it is design only.

- `ML-DEVOS-RFC-017.md` — S5 Capability & Permission Gateway. `IMPLEMENTED AND CLOSED` by `ML-DEVOS-ADR-015` / `D-065`. The design was proposed under `D-058`, approved by `ML-DEVOS-AS-077`, implemented under `D-063` (Context Bootstrap V0 Trial #1), remediated per `ML-DEVOS-AS-082`, and accepted by `ML-DEVOS-AS-083`. Defines provider-neutral capability descriptors (actor/role, project, provider, action, resource scope, environment, expiry, credential-class requirement, consequence tier), a pure `evaluate(request, policy) -> ALLOW/DENY` decision function with stable denial-reason codes, default-deny handling for every unknown axis, an explicit technical-capability/governance-authority/risk-acceptance separation (with a fixed non-authority disclaimer on every decision), least-privilege/revocation/expiry/stale-policy-version behavior, credential-class (never credential-value) requirements, sensitive-operation consequence-tier gates, five bounded provider adapter boundaries (shell/GitHub/Cloudflare/MCP/browser), audit-event minimum fields, and reference-only composition with S3 Task Contracts and S4 Task State. The accepted implementation is the repository-local decision library in `devos/capabilities/` (`status: IMPLEMENTED`, `executable_runtime_present: false`). It is not wired into S3/S4 or any runtime, implements no later-phase (S6/S7/S8/S9) mechanism, and grants no governance authority (Capability != Authority).
