# RFCs

Filed RFCs live here as `ML-DEVOS-RFC-<NNN>.md`, using `../../templates/RFC_TEMPLATE.md`. Numbering is sequential starting at `001`, never reused. See `../../governance/change-policy/CHANGE_GOVERNANCE_POLICY.md` §3 for what an RFC is (and is not) evidence of.

## Current contents

- `ML-DEVOS-RFC-014.md` — MaisogLabs Skills Foundation V0.1 discovery/architecture proposal, incorporating the Portable Knowledge Treasury discovery (`D-039`/`D-040`/`D-041`). Defines the Skill-vs-Governance/Brain/ADR/Capability boundary; recommends `.agents/skills/` as the canonical skill payload (with a thin Claude Code bridge) per a corrected, evidence-backed compatibility matrix showing 3-of-4 native repo-client support (`ML-DEVOS-AS-045` finding `AS45-F007` identified a materially false Gemini CLI claim in the prior revision, corrected in Remediation Cycle 2 — `AS-047` is the unrelated repository-visibility correction), while still leaving the final choice to Paulo's explicit gate; provides complete per-skill discovery contracts and an explicit provider-neutral SKILL CHECK routing sequence for the 4-skill V0.1 set (Governance/Traceability Audit, Architect Review/Sync, Implementation Handoff, Project Orientation/State Recovery — Knowledge/Realization Capture removed per `AS42-F004`); a consequence-tiered external-skill security/lifecycle model (`AS42-F005`/`AS44-J`); and a full Portable Knowledge Treasury design — a routing protocol (not a store) over existing canonical destinations, with a disclosure/storage model corrected for the repository's current private visibility (`ML-DEVOS-AS-047`/`D-041`) distinguishing disclosure class from Git-storage suitability, two-axis (type/disclosure) classification, canonical-destination-first deduplication, and an explicit "lightweight governed procedure, not a Skill" direction for Knowledge Capture in V0.1 (`AS44-F`). Discovery/design only — no skill file, canonical/provider-adapter directory, or Treasury implementation is created; no S3/S4+/S5/S7/S9 mechanism is implemented.
- `ML-DEVOS-RFC-013.md` — Sentinel S3 Typed Task Contracts architecture proposal. Defines a compact machine-readable task contract for authorized scope, acceptance criteria, intended claims, and required evidence provenance; explicitly excludes S4 state machinery, S7 evidence storage/QA, S9 Evidence Gate, CI/rulesets, remote resources, deployment, and main merge.
