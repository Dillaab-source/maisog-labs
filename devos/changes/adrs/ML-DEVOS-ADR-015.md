## Decision

Sentinel adopts the S5 Capability & Permission Gateway V1 as active, implemented architecture: a repository-local, deterministic capability/permission decision library under `devos/capabilities/` that answers only the CAN question — whether a specific (actor role, project, provider, action, resource, environment) combination is technically permitted under a pinned policy version, the live revocation list, and a trusted evaluation time.

- `evaluate.mjs` — the pure five-argument internal core `evaluate(subjectContext, requestIntent, policy, revocationList, evaluationContext)`:
  - no clock, randomness, or I/O;
  - default deny with the single canonical 14-code `ML-DEVOS-RFC-017` §4 denial vocabulary;
  - deterministic project/resource precedence, with any top-rank tie denied as `AMBIGUOUS_POLICY_MATCH`;
  - policy-version pinning, live revocation override, trusted-time expiry, and class-only credential checks.

  It is deliberately not exported from the public entry.
- `trusted-context.mjs` — the in-process branded trusted-context boundary and the only place minters exist. Minters are created only inside `createGateway()` and passed only to the five statically imported adapter factories. No module exports, returns, or accepts a callback for a minter.
- `adapters/` — exactly five static V1 adapters: `shell`, `github`, `cloudflare`, `mcp`, `browser`. There is no dynamic plugin discovery. An adapter's `request(requestIntent)` is the only caller-facing decision surface, and each applies its own canonicalization contract.
- `canonical.mjs` — the per-provider canonicalization contracts, including the platform-aware `shell` form (POSIX `/…`, Windows drive `C:/…`, UNC `//server/share/…`, always `/`-separated).
- `validate-capability-policy.mjs` — the zero-dependency policy validator:
  - it enforces structure, the bounded resource grammar, canonical literals and stems, and class-only credentials;
  - it applies the `ML-DEVOS-RFC-017` §8 sensitive-operation tier rule at load time only;
  - it rejects any secret-shaped value;
  - it rejects the whole document on any error.
- `audit.mjs` — the separately constructed `AuditEnvelope`, whose `event_id`, `timestamp`, and `evidence_provenance` are always caller-supplied and never generated by `evaluate()`.
- `vocabulary.mjs`, the draft-07 structural schemas, and the bounded valid/invalid policy fixtures.
- Focused tests: `tests/capabilities-core.test.mjs`, `tests/capabilities-gateway.test.mjs`, `tests/capabilities-bypass.test.mjs`, `tests/capabilities-shell-platform.test.mjs`.

The reserved root `devos/capabilities/` moves to `status: IMPLEMENTED` in `devos/devos-manifest.json`, with `closure_ref` naming this ADR and `executable_runtime_present` remaining `false`.

**Capability != Authority** (`CORE-002`, `CORE-008`). Every `CapabilityDecision`, `ALLOW` or `DENY`, carries the fixed, non-reword-able non-authority disclaimer. An `ALLOW` never grants governance authority, certifies that an action should happen, accepts risk, or satisfies any merge, deployment, or production-write approval requirement. A `DENY` blocks regardless of any governance authorization.

## Context

`ML-DEVOS-RFC-017` proposed the S5 design under `D-058`'s proposal/audit-only authorization, and `ML-DEVOS-AS-077` gave final design approval after two design remediation cycles. `D-063` authorized one bounded implementation cycle as Context Bootstrap V0 Trial #1. It required the `ML-DEVOS-AS-077` descriptor-expiry wording reconciliation: a descriptor absent from a newer policy version is "not grantable to new attempts after supersession", while an attempt already pinned to the older version keeps it until expiry or live revocation.

The original implementation (`d589a16b8256232edd029593d653335913619125`) was reviewed by `ML-DEVOS-AS-082`, which returned `CHANGES_REQUESTED` on two blockers:

- **`AS82-F001` — caller-acquirable trusted-context minters.** The original `trusted-context.mjs` exported a generic `registerAdapters(factory)` surface. On first call it handed its caller every genuine minter, and sealing the registry afterwards did not revoke minters already released. An ordinary same-process caller could therefore import it before the real registry, retain genuine minters, mint branded subject/evaluation contexts with chosen facts, and obtain a trusted decision from the raw `evaluate()` core. Remediation removed that surface entirely.
  - Minters now exist only inside `createGateway()` in `trusted-context.mjs`, and are passed only to the statically imported adapter factories, which keep them in a closure.
  - Intrinsics used on branded values are captured at module load.
  - Adversarial fresh-process regression tests harvest every production export (early caller) and patch intrinsics after load (late caller), and require zero usable minters, zero forged direct-core `ALLOW`s, and zero leaked genuine contexts.
- **`AS82-F002` — POSIX-only shell canonicalization.** The original shell contract required a leading `/`, so a normal Windows absolute path such as `C:\repo\file.txt` was rejected. Remediation made the contract platform-aware: POSIX, Windows drive, and UNC families, emitted with `/` separators. Resolution uses the host's native path semantics and filesystem, and preserves:
  - the absolute-path requirement;
  - per-component symlink resolution with OS `..` semantics;
  - fail-closed dangling, unresolvable, and escaping paths;
  - deliberate handling of not-yet-existing tails;
  - segment-aware trusted-root confinement.

  Windows behavior is covered by running the production resolver under `path.win32` over a modeled Windows filesystem.

The remediation commit `06b5bef3d1e495db95cd52508ea8fc8ed9d7242e` was reviewed by `ML-DEVOS-AS-083`, which closed both findings and technically accepted the S5 V1 implementation. `ML-DEVOS-AS-084`'s D.1 Pre-decision Closure Preflight confirmed the closure package was internally consistent and bounded. `D-065` then authorized this closure.

## Alternatives considered

See `ML-DEVOS-RFC-017`'s own "Alternatives considered":
- folding S5 into S4's kernel;
- adopting an external policy-as-code engine such as OPA/Rego or Casbin;
- per-adapter local allow/deny decisions;
- a pre-materialized permission matrix;
- a governance-authority bypass for a missing capability.

For the trusted-context boundary, the accepted design keeps the non-cryptographic, in-process V1 mechanism that `ML-DEVOS-RFC-017` §3 permits, rather than a cryptographic attestation or process-isolation scheme. `AS82-F001` was remediated within that model by removing the caller-facing minter-release surface, not by redesigning it.

## Rationale

A pure decision function over explicit trusted and untrusted arguments, reached only through bounded adapter wrappers, gives Sentinel its first technically checkable enforcement point for `CORE-002`/`CORE-008` and `TRUST_BOUNDARIES.md` TB-7. It does this without conflating capability with governance authority, and without prematurely building S6 isolation, S7 evidence storage, S8 orchestration, or S9 evidence-sufficiency judgment. S3 Task Contracts and S4 task records are referenced only by opaque `contract_ref`/`task_id` strings and are never read, re-validated, or wired.

## Consequences

Sentinel gains a real, testable capability/permission decision library:
- fail-closed on every unknown axis;
- deterministic over already-canonical resources;
- resistant to arbitrary-caller forgery of trusted subject or time facts;
- stable for in-flight attempts through policy-version pinning, while still reachable by emergency revocation;
- free of any credential secret value.

### Accepted residual limits (non-cryptographic, in-process V1)

Disclosed by `ML-DEVOS-RFC-017` §3/§9 and accepted by `ML-DEVOS-AS-083`, not claimed solved:

- code that patches intrinsics or installs module-loader hooks before the brand module loads, or that edits source, is not stopped;
- a registered adapter that lies, or a gateway constructed with a lying trusted host, is not stopped — whoever calls `createGateway()` is the trusted embedder;
- the brand is an in-process boundary, not sandbox or process isolation; stronger isolation belongs to later, separately authorized capability work.

`ML-DEVOS-AS-083`'s non-blocking observations are recorded here:
- closing `AS82-F001` leaves several raw-core defensive branches reachable only by a holder of genuine brands, and they are retained as defense in depth;
- an adapter answers a foreign provider name with `MALFORMED_REQUEST` while the raw core retains `UNKNOWN_PROVIDER`.

### No runtime integration

`devos/capabilities/`'s `executable_runtime_present` remains `false`. S5 is an implemented repository-local decision library. No active operational Sentinel runtime, orchestrator, CI path, or tool-call wrapper invokes it as an enforcement service, and closure does not wire it into S3, S4, or any tool-execution path. This is the same behavior-based test `ML-DEVOS-RFC-015` established and `ML-DEVOS-ADR-013`/`ML-DEVOS-ADR-014` applied. Until a separately authorized integration wires an adapter wrapper's decision to an actual call site, a `DENY` is advisory at any caller that ignores it (`ML-DEVOS-RFC-017` misuse case 1).

### Evidence classification

Per `ML-DEVOS-AS-083`:
- **`ACTOR_REPORTED`** — the Builder's command execution:
  - the vulnerable pre-fix bypass reproduction;
  - zero minters/bypass/leaks after the fix;
  - focused S5 tests 50/50;
  - all 15 targeted mutation regressions killed;
  - full repository suite 606/606;
  - validators passing;
  - traceability with the known errors only.

  The Architect could not run the exact snapshot in an equivalent local runtime.
- **`INDEPENDENTLY_INSPECTED`** — the Architect's review of:
  - branch ancestry and the bounded delta;
  - STATE/CURRENT_HANDOFF identity binding;
  - removal of the minter-registration export and the static minter flow;
  - non-export of raw `evaluate()`;
  - the platform-aware shell forms and resolver/confinement logic;
  - the regression-test source;
  - unchanged hard boundaries.

  The Architect separately sanity-checked the Windows/POSIX normalization semantics under Node path behavior, which is not represented as reproduction of the Builder's suite.
- **None:** no `RUNTIME_OBSERVED` evidence exists or is claimed. S5 makes no production or runtime claim.

The closure turn's own fresh verification is recorded in its Context Bootstrap handoff and likewise remains `ACTOR_REPORTED` until D.2.

### Traceability debt carried forward

The known `missing-canonical-target` errors `CORE-022` and `WEB-REQ-009` are carried forward unchanged (`OBL-015`), neither suppressed nor reinterpreted by this closure.

## Version consequence

This is a backwards-compatible new Sentinel subsystem/capability: deterministic capability/permission decision machinery and bounded provider adapters. It does not change the actor model, the source-of-truth rule, the meaning of any existing `CORE-*` rule, or prior S3/S4 closure semantics. Per `VERSIONING_POLICY.md`'s MINOR criterion and `ML-DEVOS-AS-084`'s version disposition:

`v1.7.0 → v1.8.0`

`devos/devos-manifest.json`'s `sentinel_capability_baseline` names this ADR and `D-065` as this transition's baseline pointer, and its descriptive current-baseline entry reads v1.8.0. One S5 `closure_history` entry is appended. No `CORE-*` rule changes. `manifest_version` remains exactly `"1"`. No frozen-architecture amendment is required: `ML-DEVOS-ARCH-001` §4–§5 already names the Capability Registry/Gateway role S5 fulfills, so its identity, version, status, actor model, and source-of-truth rule are unchanged.

## Explicitly not implemented

This ADR does not implement or authorize:

- wiring S5 into S3, S4, tool execution, CI, or any runtime enforcement path;
- S6 isolation, S7 Evidence/QA Plane, S8 Orchestrator, S9 Evidence Gate, S10 CI/rulesets, S11–S14;
- Context Plane CP-4+ or Model Router V0;
- dynamic plugin discovery or an external/live policy service;
- any `CORE-*` rule change, credentials or secret values, remote resources, deployment, production writes, protected/main merge, or PR #10 merge.

This ADR's adoption, `devos/capabilities/`'s `IMPLEMENTED` status, and the `v1.8.0` transition are not, individually or together, authority for any later phase.
